# Release Notes Format

Release notes are autogenerated by the GitHub Actions workflow (`.github/workflows/release.yml`) whenever a commit with a release marker is pushed to `main`. The workflow creates a draft release so entries can be sorted before publishing.

## Triggering a release

Commit a release marker on `main`:

```
[RELEASE vVERSION#TITLE]
```

- `VERSION` is the new semver (e.g. `1.2.3`) without a `v` prefix.
- `TITLE` becomes the release title: `vVERSION: TITLE`.

The workflow tags `vVERSION`, collects the commits since the previous tag, and creates a draft release.

## Autogenerated body

Always starts with `## What's Changed`:

```
## What's Changed

- Commit message 1
- Commit message 2
- ...
```

- Patch release (only the PATCH in semantic versioning increments): list the changes directly, no headers.
- Minor or major release: append headers so the entries can be sorted into them:

```
### Added
-

### Improved
-

### Fixed
-

### Breaking Changes
-
```

## Commit filtering

The following commits are excluded from the notes:

- The release marker commit itself (`[RELEASE vVERSION#TITLE]`).
- Commits whose message contains `[RELEASE IGNORE]` (case-insensitive).
- Commits whose message is exactly `Update docs` (case-insensitive).

## Attribution

Any commit not authored by the maintainer's email (`jeremytheking2013@gmail.com`) gets its GitHub username appended to the entry:

```
- Some change (Thanks @dependabot!)
```

This includes automated commits such as Dependabot's.

## After the draft is created

The release is created as a draft. Sort the bullet entries into the matching headers, fill in anything missing, and then publish it.
